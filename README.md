# Draw Your Font RU

Версия `1.6.0`. Инструмент для создания русского рукописного шрифта из машинно-читаемого шаблона или обычной фотографии. Обработка фотографий, редактирование глифов и личная библиотека выполняются в браузере. Общая библиотека использует собственный Node.js-сервер.

## Рабочий цикл

1. Выбрать новый PDF-шаблон или ручной режим для готовой фотографии.
2. Распознать страницы и исправить символы, базовую линию, метрики и кернинг.
3. При необходимости включить связный русский почерк.
4. Собрать TTF, WOFF, WOFF2, CSS и ZIP.
5. Выбрать действие:
   - `Добавить в мою библиотеку` — сохранить файлы и проект только в текущем браузере;
   - `Опубликовать в общей библиотеке` — отправить готовые файлы на сервер для всех посетителей.

## Возможности редактора

- многостраничный PDF с угловыми метками и контрольными суммами;
- исправление перспективы и автоматическое разрезание страницы;
- ручной режим для старых шаблонов, тетрадей и произвольных фотографий;
- кисть, ластик, отмена, повтор, метрики и кернинг;
- импорт, экспорт и автосохранение проекта DYFR;
- связные формы `isol`, `init`, `medi`, `fina`;
- OpenType `GSUB` с `calt/rlig` и `GPOS` с `curs`;
- настоящая базовая линия и нижние элементы `д`, `р`, `у`, `ф`, `щ`, `ц`;
- многострочный предпросмотр с переносом слов и ручными переводами строк.

## Моя библиотека

Личная библиотека хранится в IndexedDB конкретного браузера и профиля. В неё записываются TTF, WOFF, WOFF2, CSS, ZIP и полный проект DYFR. Пользователь может скачать файлы, удалить запись или снова открыть проект в редакторе.

Личная библиотека не видна другим посетителям и может исчезнуть при очистке данных сайта. Важные проекты нужно дополнительно экспортировать.

## Общая библиотека

Общая библиотека находится на сервере и доступна всем посетителям одного развёрнутого экземпляра сайта.

Перед публикацией пользователь указывает имя автора, описание, лицензию и подтверждает право на публикацию. Поддерживаются:

- `SIL Open Font License 1.1`;
- `CC0 1.0`;
- `CC BY 4.0`.

На сервер отправляются только готовые файлы шрифта и публичные метаданные. Проект DYFR, маски и фотографии не отправляются.

Сервер:

- проверяет сигнатуры TTF/OTF, WOFF, WOFF2 и ZIP;
- ограничивает размер тела запроса, отдельных файлов, общий объём и количество публикаций;
- очищает и ограничивает текстовые поля;
- записывает публикации атомарно через временную папку;
- хранит только SHA-256 ключа владельца и не выдаёт его в публичном API;
- разрешает обновление и удаление только владельцу или администратору;
- ограничивает частоту операций публикации;
- закрывает серверные данные, исходники сервера и внутренние каталоги от статической раздачи;
- устанавливает CSP и другие защитные HTTP-заголовки.

Ключ владельца хранится только в браузере автора. После очистки данных браузера автор потеряет возможность управлять публикацией через интерфейс. Администратор может использовать закрытый `DYFR_ADMIN_TOKEN` для аварийного удаления или обновления.

## Серверные данные

По умолчанию публикации записываются в:

```text
data/public-fonts/<publication-id>/
├── metadata.json
├── ttf.ttf
├── woff.woff
├── woff2.woff2
├── css.css
└── zip.zip
```

Папка `data/` исключена из Git. На производственном сервере её нужно хранить на постоянном диске и включать в резервные копии.

## Установка

```bash
npm install
npm run build:runtime
```

## Запуск с общей библиотекой

```bash
npm start
```

По умолчанию сервер слушает `0.0.0.0:8000` и хранит каталог в `data/public-fonts`.

Параметры командной строки:

```bash
node server.mjs --host 127.0.0.1 --port 8000 --data-dir /srv/draw-your-font-data/public-fonts
```

Переменные окружения:

```text
HOST                      адрес прослушивания
PORT                      порт
DYFR_DATA_DIR             постоянная папка общей библиотеки
DYFR_ADMIN_TOKEN          закрытый аварийный ключ администратора
DYFR_TRUST_PROXY          1 только за доверенным reverse proxy
DYFR_MAX_PUBLIC_BYTES     общий лимит каталога, по умолчанию 5 GiB
DYFR_MAX_PUBLIC_FONTS     максимум публикаций, по умолчанию 10000
```

Пример находится в `.env.example`.

Основная страница:

```text
http://localhost:8000/
```

Личная и общая библиотека:

```text
http://localhost:8000/library.html
```

Статический запуск через `python -m http.server` оставляет рабочими редактор и личную IndexedDB-библиотеку, но публикация и общий каталог недоступны.

## Docker

```bash
export DYFR_ADMIN_TOKEN="$(openssl rand -hex 32)"
docker compose up -d --build
```

Данные сохраняются в именованном volume `draw-your-font-data`. Для размещения контейнера за Nginx задайте `DYFR_TRUST_PROXY=1`. Не включайте этот режим при прямом публичном доступе к Node-порту.

## VPS, Nginx и systemd

Минимальная схема:

```text
Интернет
   ↓
Nginx или Caddy с HTTPS
   ↓
node server.mjs
   ↓
постоянная папка DYFR_DATA_DIR
```

В каталоге `deploy/` находятся:

- `nginx.conf.example`;
- `draw-your-font.service.example`.

Рекомендации:

- использовать HTTPS;
- сохранять заголовок `Host` при проксировании;
- установить `DYFR_TRUST_PROXY=1`, только когда запросы к Node принимает доверенный прокси;
- дать право записи в `DYFR_DATA_DIR` только пользователю приложения;
- регулярно архивировать папку данных;
- контролировать свободное место и серверные лимиты;
- не раздавать `data/` отдельным веб-сервером.

Администраторское удаление публикации:

```bash
curl -X DELETE \
  -H "Origin: https://fonts.example.com" \
  -H "Authorization: Bearer $DYFR_ADMIN_TOKEN" \
  https://fonts.example.com/api/public-fonts/PUBLICATION_ID
```

## Проверки

```bash
python -m pip install fonttools brotli websocket-client uharfbuzz
npm run test:all
```

Полный цикл в Chromium, Firefox и WebKit:

```bash
npx playwright install chromium firefox webkit
npm run test:cross-browser
```

Автотесты охватывают runtime, PDF и распознавание, TTF/WOFF/WOFF2, FontTools, HarfBuzz, GSUB/GPOS, личную IndexedDB-библиотеку, серверный API, ограничения прав и квот, две кнопки после сборки, публичный каталог, скачивание и удаление владельцем.
