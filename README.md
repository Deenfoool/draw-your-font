# Draw Your Font RU

Версия `1.6.0`. Инструмент для создания русского рукописного шрифта из машинно-читаемого шаблона или обычной фотографии. Обработка фотографий, редактирование глифов и локальная библиотека выполняются в браузере. Общая библиотека использует собственный Node.js-сервер.

## Рабочий цикл

1. Пользователь выбирает новый PDF-шаблон или ручной режим для готовой фотографии.
2. Заполняет и фотографирует страницы либо размечает обычное изображение.
3. Исправляет символы, базовую линию, метрики и кернинг.
4. При необходимости включает связный русский почерк.
5. Собирает TTF, WOFF, WOFF2, CSS и ZIP.
6. Выбирает одно из двух действий:
   - `Добавить в мою библиотеку` — сохранить файлы и проект только в текущем браузере;
   - `Опубликовать в общей библиотеке` — отправить готовые файлы на сервер для всех посетителей.

## Создание и редактирование шрифта

- машинно-читаемый многостраничный PDF с угловыми метками и контрольными суммами;
- автоматическое исправление перспективы и разрезание страницы на ячейки;
- резервный ручной режим для старых шаблонов, тетрадей и произвольных фотографий;
- кисть, ластик, отмена, повтор, метрики и кернинг;
- сохранение и восстановление проекта DYFR;
- связные формы `isol`, `init`, `medi`, `fina`;
- OpenType `GSUB` с `calt/rlig` и `GPOS` с `curs`;
- настоящая базовая линия и нижние элементы `д`, `р`, `у`, `ф`, `щ`, `ц`;
- многострочный предпросмотр с переносом слов и ручными переводами строк.

## Моя библиотека

Личная библиотека хранится в IndexedDB конкретного браузера и профиля. В неё записываются:

- TTF, WOFF, WOFF2, CSS и ZIP;
- полный проект DYFR с масками, метриками и настройками;
- обычный или связный режим;
- текст предпросмотра и сведения о файлах.

Пользователь может скачать файлы, удалить запись или снова открыть проект в редакторе. Личная библиотека не видна другим посетителям и может исчезнуть при очистке данных сайта, поэтому важные проекты нужно дополнительно экспортировать.

## Общая библиотека

Общая библиотека находится на сервере и доступна всем посетителям одного развёрнутого экземпляра сайта.

Перед публикацией пользователь указывает:

- имя автора;
- описание;
- лицензию `SIL OFL 1.1`, `CC0 1.0` или `CC BY 4.0`;
- подтверждение права на публикацию.

На сервер отправляются только готовые файлы шрифта и публичные метаданные. Проект DYFR, маски и фотографии в общий каталог не отправляются.

Сервер:

- проверяет сигнатуры TTF/OTF, WOFF, WOFF2 и ZIP;
- ограничивает размеры тела запроса и каждого файла;
- очищает и ограничивает текстовые поля;
- записывает публикацию атомарно через временную папку;
- не выдаёт секретный ключ владельца в общем API;
- позволяет обновлять и удалять публикацию только по ключу владельца;
- ограничивает частоту операций публикации по IP;
- запрещает доступ к папке серверных данных через статический сайт;
- устанавливает CSP и другие защитные HTTP-заголовки.

Ключ владельца хранится только в браузере автора. Потеря данных браузера означает потерю возможности обновить или удалить публикацию через интерфейс. Администратор сервера по-прежнему может удалить соответствующую папку вручную.

## Структура серверных данных

По умолчанию публикации записываются в:

```text
data/public-fonts/<publication-id>/
├── metadata.json
├── ttf.ttf
├── woff.woff
├── woff2.woff2
├── css.css
└── zip.zip
```

Папка `data/` исключена из Git. На производственном сервере её нужно хранить на постоянном диске и включать в резервные копии.

## Установка и сборка runtime

```bash
npm install
npm run build:runtime
```

Сборщик проверяет непрерывность архивных частей, синтаксис прямых модулей и печатает SHA-256 каждого активного исходника.

## Запуск с общей библиотекой

```bash
npm start
```

По умолчанию сервер слушает `0.0.0.0:8000` и хранит каталог в `data/public-fonts`.

Параметры:

```bash
node server.mjs --host 127.0.0.1 --port 8000 --data-dir /srv/draw-your-font-data
```

Переменные окружения:

```text
HOST
PORT
DYFR_DATA_DIR
```

Основная страница:

```text
http://localhost:8000/
```

Личная и общая библиотека:

```text
http://localhost:8000/library.html
```

Статический запуск через `python -m http.server` оставляет рабочими редактор и личную IndexedDB-библиотеку, но публикация и общий каталог при таком запуске недоступны.

## Развёртывание на сервере

Минимальная схема:

```text
Интернет
   ↓
Nginx или Caddy с HTTPS
   ↓
node server.mjs
   ↓
постоянная папка DYFR_DATA_DIR
```

Рекомендации:

- запускать Node-процесс через systemd, Docker или другой процесс-менеджер;
- использовать HTTPS;
- сохранять заголовок `Host` при обратном проксировании;
- ограничить доступ на запись к папке данных только пользователем приложения;
- регулярно архивировать `DYFR_DATA_DIR`;
- ограничить размер диска и следить за свободным местом;
- не публиковать папку `data` отдельным веб-сервером.

## Проверки

```bash
python -m pip install fonttools brotli websocket-client uharfbuzz
npm run test:all
```

Полный цикл в Chromium, Firefox и WebKit:

```bash
npx playwright install chromium firefox webkit
npm run test:cross-browser
```

Автотесты охватывают:

- восстановление runtime и синтаксис активных модулей;
- PDF, распознавание страниц и ручной режим;
- TTF, WOFF, WOFF2, CSS и ZIP;
- FontTools, HarfBuzz, GSUB и GPOS;
- базовую линию и отрицательный `yMin` нижних элементов;
- личную IndexedDB-библиотеку;
- серверный API публикации, скачивания, обновления и удаления;
- запрет операций без подтверждения прав или ключа владельца;
- две кнопки после сборки;
- публичный каталог, поиск, предпросмотр и удаление владельцем;
- Chromium, Firefox и WebKit.
