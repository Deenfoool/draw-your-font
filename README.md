# Draw Your Font RU

Полностью браузерный инструмент для создания русского рукописного шрифта. Пользователь печатает размеченный PDF, заполняет его от руки, фотографирует страницы и получает устанавливаемые TTF, WOFF и WOFF2. Изображения и данные проекта обрабатываются локально и не отправляются на сервер.

## Готовый рабочий цикл

1. Создание печатного A4-шаблона для русского алфавита, цифр, знаков или собственного набора.
2. Автоматическое определение страницы, поворота и четырёх угловых меток.
3. Исправление перспективы фотографии и разрезание листа на известные ячейки.
4. Автоматическое назначение `А–Я`, `а–я`, `Ё/ё`, цифр и знаков.
5. Проверка качества, ручная кисть и ластик, перемещение и масштабирование каждого глифа.
6. Автоматические метрики, индивидуальные боковые поля и ручной/автоматический кернинг.
7. Необязательный связный режим с начальными, средними и конечными формами строчных букв.
8. Сборка, проверка и скачивание TTF, WOFF, WOFF2, CSS и общего ZIP-пакета.
9. Экспорт, импорт и локальное автосохранение проекта.

## Этап 1: универсальная разметка фотографии

Ручной резервный режим остаётся доступен для старых листов и любых произвольных фотографий:

- адаптивная компенсация теней и неравномерного освещения;
- бинаризация и морфологическая очистка;
- поиск связанных компонентов;
- объединение точек и диакритики `Ё/ё/Й/й`;
- сортировка по строкам;
- ручное объединение, разделение и удаление рамок;
- редактирование подписей и экспорт JSON.

## Этап 2: машинно-читаемый PDF-шаблон

Каждая новая страница содержит:

- четыре различные угловые метки, позволяющие определить ориентацию;
- защищённый контрольной суммой машинный код страницы;
- идентификаторы набора, сетки, номера страницы и общего количества символов;
- базовую линию, высоту строчных, линию выносных элементов и центр ячейки;
- контрольную линейку и нумерацию.

Основной русский набор содержит 88 символов и помещается на двух листах A4.

## Этап 3: настоящий шрифт

Собственный сборщик создаёт таблицы TrueType `head`, `hhea`, `maxp`, `OS/2`, `hmtx`, `cmap`, `loca`, `glyf`, `name`, `post` и `kern`. Контуры строятся из масок с сохранением внутренних отверстий. Перед скачиванием проверяются сигнатуры, таблицы, Unicode-карта и контрольные суммы.

## Этап 4: автоматический сканер и редактор

- множественная загрузка фотографий;
- повороты 0°, 90°, 180° и 270°;
- проективное выпрямление листа;
- определение набора, сетки и номера страницы;
- несколько независимых декодеров JPEG, PNG, WEBP и локальный резервный HEIC/HEIF-декодер;
- нормализация контраста и повторные попытки распознавания;
- ручная установка четырёх углов, если метки размыты;
- передача обычной фотографии без меток в универсальный ручной режим;
- отчёт о пропущенных и повторных страницах;
- предупреждения о пустых, слишком маленьких, высоких или касающихся края символах;
- кисть, ластик, отмена и повтор;
- смещение и масштабирование глифа;
- индивидуальные метрики и визуальное сравнение по общей базовой линии;
- автоматические интервалы и предложения кернинга;
- ручное редактирование кернинговых пар;
- проект формата DYFR v4 с RLE-сжатием масок;
- автосохранение в браузере и перенос проекта JSON между устройствами.

## Этап 5: связный русский почерк

Связный режим не заменяет обычный: его можно включать отдельно после создания проекта.

- для каждой поддерживаемой строчной буквы автоматически создаются формы `isol`, `init`, `medi` и `fina`;
- начальная форма соединяется справа, средняя — с обеих сторон, конечная — слева;
- пробелы, знаки препинания и отключённые пользователем стороны разрывают соединение;
- точки входа и выхода можно перетаскивать прямо на букве;
- регулируются высота соединения, длина хвоста, толщина и плавность;
- каждую из четырёх форм можно отдельно сдвигать и масштабировать;
- предпросмотр показывает слово и фактически выбранную последовательность форм;
- итоговый шрифт содержит OpenType `GSUB` со скриптами `DFLT/cyrl` и функциями `calt/rlig`;
- таблица OpenType `GPOS` с функцией `curs` хранит входные и выходные якоря и совмещает соседние буквы;
- CSS из пакета явно включает `rlig`, `calt` и `curs`;
- обычные Unicode-символы остаются привязаны к одиночным формам, поэтому шрифт не ломается в программах без поддержки контекстной подстановки.

Рекомендуемый порядок:

1. Сначала исправьте базовые глифы и метрики.
2. Включите «Связный почерк».
3. Проверьте точки соединения на словах `мама`, `школа`, `ручка`, `русский`.
4. Подправьте проблемные буквы и отдельные формы.
5. Соберите шрифт обычной кнопкой «Собрать шрифт».

## Автономные браузерные runtime

`fonteditor-core 2.6.3`, Google WOFF2 WebAssembly и резервный HEIC/HEIF-декодер собираются в локальные файлы внутри `vendor`. Опубликованная версия не загружает эти модули с CDN.

```bash
npm install
npm run build:runtime
```

Команда также восстанавливает крупные проверяемые модули из `source-parts` и сверяет SHA-256 связного движка и интерфейса.

## Запуск

```bash
npm install
npm run build:runtime
python -m http.server 8000 --bind 0.0.0.0
```

Откройте `http://localhost:8000`. В GitHub Codespaces откройте перенаправленный порт 8000 в отдельной вкладке.

## Проверки

Детерминированные тесты алгоритмов, FontTools, HarfBuzz и Chromium:

```bash
npm run test:all
```

Полный цикл в Chromium, Firefox и WebKit:

```bash
npx playwright install chromium firefox webkit
npm run test:cross-browser
```

Автотесты охватывают:

- тени, шум, диакритику и ручные правки;
- PDF и машинный код страницы;
- все четыре поворота и перспективное искажение;
- резервное декодирование после `InvalidStateError`;
- отсутствие, повтор и объединение нескольких страниц;
- сохранение и восстановление масок, метрик и связных настроек;
- TTF/WOFF/WOFF2, Unicode `А/Ё`, ZIP и CSS;
- независимый разбор созданного шрифта библиотекой FontTools;
- точный HarfBuzz-шейпинг `мама → init, medi, medi, fina`;
- разрыв соединения пробелом;
- наличие `GSUB`, `GPOS`, `calt`, `rlig`, `curs`, `DFLT` и `cyrl`;
- наличие входных и выходных якорей в Cursive Attachment lookup типа 3;
- установку результата через браузерный `FontFace`;
- связную сборку в Chromium, Firefox и WebKit;
- локальные WOFF2 и HEIC runtime без внешнего CDN.

## Публикация

Workflow GitHub Actions сначала запускает детерминированные проверки, FontTools/HarfBuzz и Chromium, затем отдельный полный цикл в Chromium, Firefox и WebKit. Только после прохождения обоих заданий он заново собирает локальные runtime и публикует статический сайт в GitHub Pages.
